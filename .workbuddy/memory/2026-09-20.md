## UI 重构：App 图标式首页 + 详情页（v3.2）

用户需求演进：先要求去掉 sidebar/横向 tab 改为单页分区；后改为「手机 App 图标首页，点击进入功能」。

### 最终方案（v3.2）
- `src/index.html`：移除 aside.sidebar、横向 tab、锚点导航。页面分两个视图：
  - `#launcher-view`：功能中心首页，按模块分组的 tile 网格（每个 tile 带 data-step，class 含 step-link 以复用旧绑定）
  - `#detail-view`：详情页（detail-header 返回按钮 + detail-title），内含全部 section 卡片
- `src/lib/css/main.css`：删除 sidebar/horizontal-tabs/module-group 样式；新增 launcher/tile/detail 样式；`.step-section { display:none }` + `.step-section.active { display:block }`（类切换）
- `src/biz/ui.js`：`showSection(n)` 改为视图切换（未连接且 n∉{1,6} → 提示并跳连接设置）；`goHome()` 返回首页；`initLauncher()` 绑定返回按钮 + Esc 键；`refreshSectionLocks()` 连接成功后移除 `.needs-connection`（section）与 `.locked`（tile）
- `src/app.js`：initApp 默认 `goHome()`；连接成功后 `goHome()`（不再跳 section-5）；清理 nav-item/submenu/sidebar 事件
- `src/common/icons.js`：项目无 FontAwesome 字体，图标靠 IconMap 内联 SVG 替换。补齐 home/star/chartLine/chartPie/exclamationTriangle/code/clock/utensils/lock/ellipsisH/cog/chevronDown/networkWired + fa-file-upload/fa-search/fa-arrow-left 等映射
- 未连接锁定：section 加 `needs-connection` 类（半透明 + 卡片头 `::after`「需连接」徽标），tile 加 `locked` 类

### 关键坑
1. `replaceIcons()` 用 `outerHTML` 替换 `<i>` → 自定义类（如 tile-lock）丢失。锁图标显隐需用结构选择器 `.tile > svg:last-child`
2. 重组 HTML 时 `analysis-charts-container`（原 stats-section 内）易丢失，已移入 section-10 卡片内；用新旧文件 ID 集合 diff 验证完整性
3. dist/index.html 的构建方式：`node node_modules/webpack/bin/webpack.js --mode production`（npm .bin shim 有权限问题）
4. jest 测试 4 套件全挂是历史问题（ESM 源码被 CJS require），与 UI 无关
5. 视觉验证：`python3 -m http.server`（须 run_in_background）+ Chrome headless `--screenshot`；详情页预览需去掉 app.js script 引用（否则 goHome 会切回首页）

## v3.4：修复「找到 session 进主页却显示未连接 + 首页空白」

### 真正的根因（两个，都会被误判成 UI 问题）
1. **`src/biz/ui_layout.js` 里 `import DEFAULT_LAYOUT from "../rules/ui_layout.json"`**
   浏览器/Chrome 扩展不支持 JSON 模块导入。直接运行 src 源码（`src/` 本身就是
   一个完整可加载的 MV3 扩展目录：有 manifest.json / app.js / index.html）时，这个
   导入会让 **整个 app.js 模块图加载失败**，于是：
   - 首页只剩静态 HTML：`#connection-status-badge` 保持硬编码的「未连接」
   - `#favorites-host` / `#launcher-groups` 永远为空 → 常用功能和其他功能都不显示
   控制台报错：`Failed to load module script: ... MIME type of "application/json"`。
   修复：新增 `src/biz/ui_layout_default.js`（JS 模块形式的默认布局，仅作兜底），
   运行时优先 fetch `rules/ui_layout.json`。**禁止再用 JSON 模块导入。**
2. **`src/index.html` 的 `<script src="./app.js">` 必须保留 `type="module"`**
   src/app.js 是原生 ESM，去掉会报 `Cannot use import statement outside a module`；
   而 dist/app.js 是自包含 IIFE，用 module 方式加载同样正常 → module 是两种方式都成立的写法。

### 其他加固
- `src/app.js` initApp 重排：先完整渲染界面（replaceIcons/initLunch/initLauncher/
  updateUIState/initUiLayout/goHome/bindEvents），最后才尝试恢复 Salesforce 会话。
  校验失败**不再 early return、不再清 storage**，只在服务端明确返回会话无效
  （401/403 或 INVALID_SESSION_ID 等，见 sfConn.lastError）时才降级为未连接。
  否则 CSP/网络拦截会被误判成「未连接」。
- `src/biz/sf_service.js`：testConnection 失败时记录 `this.lastError`
  {message,errorCode,statusCode}，供上面判断「真失效」还是「被拦截」。
- `src/manifest.json`：`content_security_policy.extension_pages` 的 connect-src
  补齐全部 host_permissions 域名（之前缺 sfcrmapps.cn / sfcrmproducts.cn / .mil /
  mcas.ms / builder.salesforce-experience.com，中国区 org 的 session 校验会被 CSP 拦截）；
  web_accessible_resources 增加 `rules/ui_layout.json`。
- `src/biz/logic.js`：autodetect 成功后 `showSection(5)` → `goHome()`（走功能中心首页）。
- `marked` 之前以 `<script type="module">` 引入但 ESM 版不会挂到 window，
  `window.marked` 一直 undefined（Markdown 静默降级为简易解析器）。
  改为在 app.js 里 `import { marked } from "./lib/js/marked.min.js"` 再赋给 window.marked，
  并删掉 index.html 里的 marked 标签。

### 验证方法（可复用）
纯静态服务验证必须自己映射 MIME（本机 python 的 mimetypes 未初始化，.js 会变成 text/plain，
Chrome 的 module 严格 MIME 检查会直接拒载）：
- `serve.py`：SimpleHTTPRequestHandler 子类，显式映射 .js→text/javascript、.json→application/json
- 在 index.html 的 `<head>` 最前注入 chrome.* API shim（storage/runtime.getURL/tabs/cookies/alarms/action），
  用 `?scenario=connected|fresh|unconnected` 预置 chrome.storage.local
- Chrome `--headless=new --no-sandbox --dump-dom`，shim 里 8s 后把渲染结果写进 `#__preview_report__`
  的 data-* 属性，grep 出来即可断言（比截图更适合做回归）
- 结果：dist 与 src 两种方式都 data-badge=已连接 / tiles=19 / groups=9 / favorites=6 / marked=function

## v3.6：修「设置里找不到布局配置」——两个真实原因

### 原因 1（关键）：已保存的自定义布局会永久盖掉默认配置
`loadUiLayout()` 原来是「storage 有就用 storage，完全覆盖默认」，于是用户只要点过一次「应用并保存」，
之后版本里新增的分组/磁贴就再也看不到（v3.5 加的 布局配置 磁贴正是这样被吃掉的）。
修复：新增 `mergeWithDefault(stored, base)` —— **用户配置决定顺序/文案/配色，默认配置决定功能是否存在**。
缺失的分组/磁贴会合并回来（分组不存在则整组追加，存在则把缺的磁贴补到该组末尾）。
同时新增顶层 `hidden: ["tile-id"]` 语义，用来真正永久隐藏磁贴（直接删 tile 只是临时的）。
`normalizeLayout` / `layoutToJsonText` 都已支持 hidden。

### 原因 2：首页底部的「设置」分组太容易被忽略
原来只是首页 9 个分组里最下面的一个分组名（不是可点入口），加上页面很长，确实可能找不到。
修复：把「设置」提到**顶部导航栏的齿轮按钮**（`#settings-nav-btn`，全局可见、任何页面都在），
点击进入新的 **设置页 `#section-21`**，里面是一个设置项列表：
连接设置(1) / 布局配置(20) / 项目说明(6) —— 每行带图标、名称、说明和右箭头。
index.html 首页布局里原来的 `settings` 分组已移除（避免出现两个「设置」）。
`showSection` 免连接白名单 → `![1,6,20,21]`；app.js bindEvents 绑定齿轮 + `.settings-row[data-goto]` 事件委托。

验证：接 `?scenario=stale`（storage 里塞一份只有 connection 分组的旧自定义布局）→ 结果 hero 标题保留「自定义首页」，
但 tiles=18 / groups=8（全部合并回来）——证明原因 1 已修。
`?settings=20` 走真实路径：settings-rows=3、labels=["连接设置","布局配置","项目说明"]、section21 active、
点「布局配置」后 section-20 active + 编辑器长度 5390。截图 `.workbuddy/screenshots/v36_*.png`
