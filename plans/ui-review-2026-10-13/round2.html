UI 统一化改造记录

nForce Tools v4.4.0 · 2026-10-13 · 针对「模块间不统一 / 说明占地方 / 按钮形状不统一 / 页面单调 / AI 味」五项
第 1–6 节按 29 个功能页横向对比量；第 7 节按 400 / 560 / 1280 三档宽度纵向量

第一轮评审报告（同目录 index.html）给的是问题清单；这一轮是**照着清单改**。 改完用 CDP 把 **29 个功能页全量量了一遍**（不靠肉眼抽看截图），所有结论都有具体数字。 唯一需要你拍板的是一处命名方向调整，标在「待确认」里。

1 · 说明块：250px → 58–78px

原来每个功能页开头是「80px 居中圆图标 + 居中 24px 大标题 + 居中说明列表」， 一屏里出现三个标题级元素。最长的 section-17 有 224 字 / 5 条，正文被挤到折叠线以下。

改成一条横向信息带：跟模块色的小方章 + 一句话摘要；「字段口径 / 筛选条件」这类 不常看但出错时要查的内容收进默认折叠的 <details>。 标题不再重复写第二遍——卡片头已经是本页标题。

头部高度 约 250px → 58px（无折叠）/ 78px（带折叠）
摘要字数 最长达 224 字 → 11–53 字

3 · 空页面：11 个结果区有了结构

11 个结果表初始带 u-hidden，空页面只剩「说明 + 一个按钮 + 一大片空白」—— 这是「页面单调」的根因。给每个结果区加了虚线描边的占位块，表格渲染出来后自动让位（纯 CSS， :has() 相邻兄弟选择器，不引 JS）。

真实取数流程下验过：占位 display:flex → 表格出现后 none → 收起后回到 flex，双向联动正常，控制台零错误。 实现上有个坑：table_utils.js 原来只写内联 style.display，:has() 判不出来， 所以补了 showContainer()/hideContainer() 同时切 u-hidden 类。

4 · 头部图标：21 个页面全是近黑色

这一条是量出来的，不是看出来的——所有页面头部图标坐在彩色底章上，但字形本身是 rgba(0,0,0,0.85)。根因：common/icons.js 用 el.outerHTML = <svg class="svg-icon"> 整体替换 <i>， <i> 上的 class 一个都不保留，所以 u-text-brand 连同 u-fs-3xl 之类的尺寸类一起消失，颜色退回继承值。

把颜色与底色收到容器上（子 svg 靠 fill="currentColor" 继承）：

.section-icon {
  background: var(--theme-bg, var(--primary-bg));
  color: var(--theme-color, var(--primary-color));
}

7 · 补充：窄栏排版

上面几节都是「29 页横向对比」量出来的。这一节是换个方向——同一页在 400 / 560 / 1280 三档宽度下量，专抓那些「只有某个宽度才露头」的问题。 三处都有具体数字，其中两处是同一类根因：0 宽度的元素和没用的预留，照样吃布局。

7.1 告警条里的按钮被压成两行

首页 Org 状态卡的告警文案（「1 项已超出配额（>100%），1 项超过 85%，3 项超过 60%」） 是个匿名文本节点，跟「查看详情」按钮同处一个 flex 行。文案一长，按钮先被压扁： 

400px：48 × 40px  ← 两行，「查看详情」竖排
1280px：66 × 23px ← 一行
.org-dash-alert-link {
  flex-shrink: 0;      /* ← 补 */
  white-space: nowrap; /* ← 补 */
}

改后 400px 也是 66 × 23 单行（文案自己换行，按钮不再变形）。

7.2 磁贴标签被省略号吃掉

这个更有意思：量出来「标签可用 73px，而 6 个汉字需要 78px」——就差 5px，于是「获取当日数据」这类全被截断。顺藤摸瓜找到两个根因。

根因一：空的锁图标容器白吃一个 gap。 .tile-lock-wrap 始终在 DOM 里（未锁定时只把里面的 svg 藏起来）， 但它是 .tile 的第三个 flex 子项——宽度 0，照样占掉一个 8px 的 gap：

.tile-lock-wrap {
  position: absolute;  /* ← 移出常规流，宽度还给 .tile-text */
  top: 0; right: 0; width: 0; height: 0;
}

根因二：星标预留有三套值。 星标是绝对定位的圆形按钮（right: 9px; width: 22px）， 得靠父级 padding-right 让位。而同一个零件写了三个数： 基础 36px、≤560px 覆盖成 28px、 常用功能区又单独 14px。三个数都不是按「星标实际多大」算的。

查 DOM 才发现关键事实：常用功能区那 4 张磁贴根本没有星标（编辑态换成底部的 ← → ×）， 所以 14px 那条不是随手写的，但它用的是「猜网格」而不是「看有没有星标」。改用 :has()：

.tile-cell > .tile { padding-right: 14px; }            /* 默认：没有星标 */
.tile-cell:has(> .tile-fav-btn) > .tile {              /* 有星标才预留 */
  padding-right: 30px;                                 /* 6px 偏移 + 22px 按钮 + 2px */
}
宽度标签被截断的磁贴标签可用宽
400px（2 列）13 / 28 → 5 / 2873px → 79px（常用功能区 87 → 95px）
560px（3 列）5 / 28→ 78px
1280px（6 列）4 / 28 → 2 / 2884px → 100px

剩下 5 个是 T-4 Outstanding（102px）、Execute Anonymous（126px）这类 本身就更长的名字，2 列 157px 的磁贴确实放不下——再挤就要动图标尺寸和星标热区了，不划算。

列数没动。 全程没碰 .tile-grid 的 minmax() 与 gap， 所以 panel-shot.mjs 里 data-tile-cols 的三处期望值（560→3 / 400→2 / 1280→6）不需要同步。 改完实测仍是 2 / 3 / 6。
