1评分总览

工程一致性已经很强，拖后腿的不是"值不统一"，而是"版式策略"和"信息架构"。

维度评分依据
设计令牌 / 变量体系 9 :root 已是唯一来源；硬编码色残留 0 处（白名单 9 种）、字号越界 0 处、通知缺 type 0 处
组件同构度 8 24 磁贴 / 29 个 section 全部由同一套模板渲染，.unified-card、.section-header 复用到位
窄栏（240–560px）适配 7 顶栏压缩、磁贴降列、表格横滚都已实现；但警示条按钮竖排、星标常显产生歧义

2三条核心结论

01

战场转移了：问题不再是「碎片化」，而是「版式策略」

2026-09 那次审计的结论是"同一个视觉决策被独立决定了 N 次"（44 种字号 / 7 种灰 / 5 套图标）。那一仗已经打完：现在硬编码颜色 0 处、字号越界 0 处、check:ui 全绿。本轮看到的所有观感问题，根因都不是"值写错了"，而是一套为 320px 侧边栏设计的居中编排，被原样用在了 1280px 宽屏上。

02

详情页戴了三顶帽子：卡片头标题 + 大圆图标 + 内容区大标题

每个 section 同时有 .ant-card-head-title 和 .section-header > .section-title，同一件事说两遍；中间再插一个 80px 的居中圆图标。宽屏下这三件套占掉一屏的三分之一，而真正的数据（表格 / 列表）被 align-items: center 压成中间一条约 600px 宽的窄带。

03

命名是当前性价比最高的收益：纯文本改动、零风险

同一个功能在三处有三个名字（磁贴「PCD 过期」→ 卡片头「获取 PCD 过期数据」→ 内容标题「获取 PCD 过期数据」），Org 看板有 4 个叫法，还有一处实际错字（磁贴「中午食乜」 vs 标题「中午吃乜」）。这些改起来只是改字符串，但不改会让每个新用户都要多猜一次。

3P0 · 影响可用性的缺陷

四条都能用纯 CSS 修完，零行为变化；但都会直接改变用户看到的页面。

P0-1

宽屏下详情页内容被压成中间一条窄带

现象

1280px 标签页里打开 Org Limits，搜索框、汇总卡、指标列表全部挤在中间约 590px 宽的一条里，左右各留 350px 空白；列表行的进度条短到看不出差异。

证据

见下方 rev-limits-tab-1280：卡片本身是 1240px 宽，但内容只有中间一小块。

根因

src/lib/css/main.css:1594

/* 子块全都被压成 min-content 宽度 */
.section-content {
  display: flex; flex-direction: column;
  align-items: center;      ← 元凶
  justify-content: center; padding: 2rem 0;
}

它本来是给"居中一行说明 + 一个按钮"的表单卡设计的，但 #org-limits-content 这类宽内容也套了同一个容器。

方案

/* main.css：容器撑满，居中交给需要居中的那一个子块 */
.section-content { align-items: stretch; }

/* 顺带补一条兜底：数据区永远撑满 */
#org-limits-content, #report-data-container,
#pcd-expired-data-container { width: 100%; }

安全性：表单卡本来就有 .unified-form { max-width: 400px; margin: 0 auto }、上传区有 max-width: 600px，所以 stretch 之后它们仍然居中，视觉不变。

P0-2

窄栏警示条里「查看详情」被挤成竖排三字

现象

400px 侧边栏下，红色警示条「1 项已超出配额…，1 项超过 85%，3 项超过 60%」换行成 3 行，右侧按钮被压成一列竖着的「查看/详情」。

证据

见下方 rev-home-panel-400 的警示条区域。

根因

src/lib/css/main.css:3097（.org-dash-alert-link）

只有 margin-left: auto，没有 flex-shrink: 0，也没有禁止换行。flex 收缩时它和文本争宽度，于是每个汉字单独折行。

方案

.org-dash-alert-link {
  flex-shrink: 0;
  white-space: nowrap;
}
/* 窄栏里改为「文案占满一行、按钮下一行右对齐」更省空间 */
@media (max-width: 560px) {
  .org-dash-alert { flex-wrap: wrap; }
}
P0-3

居中块里塞左对齐列表，两种排版互相打架

现象

「获取报表数据」的说明列表：块整体居中、列表项左对齐。换行之后每一行的左边缘都不同，读起来像被"摇晃"的散文；400px 下尤其明显，几乎无法逐条扫读。

证据

见下方 rev-report-tab-1280 与窄栏版本。

根因

main.css:1535 .section-header（align-items: center）+ 1568 .section-desc（margin: 0 auto + padding-left: 20px）

text-align: left 让字左对齐，但容器又是 align-items: center 按内容宽度收缩 —— 于是"块居中、行左对齐"，视觉锚点消失。

方案

/* 窄栏保留居中（空间小、单列读），宽屏改为左对齐版式 */
@media (min-width: 900px) {
  .section-header {
    flex-direction: row;
    align-items: center;
    text-align: left;
    gap: 12px;
  }
  .section-icon { width: 40px; height: 40px; margin: 0; border-radius: 10px; }
  .section-desc { margin: 0; }
}

窄栏那一档完全不用动 —— 现在的居中对 300px 宽度是对的。改的是"宽屏不再假装自己很窄"。

P0-4

磁贴描述在宽屏几乎被全量截断

现象

首页宽屏下 6 列磁贴，描述行几乎全是省略号：「T-4 connectivity …」「历史遗留未完…」「VVIP 客户订…」「T-4 connecti…」。描述写得再准，用户也读不到。

证据

见下方 rev-home-tab-1280 的 LTS 分组。

根因

main.css:2494 .tile-grid + 2555 .tile-desc

.tile-grid { grid-template-columns: repeat(auto-fill, minmax(176px, 1fr)); }
.tile-desc { white-space: nowrap; text-overflow: ellipsis; overflow: hidden; }

1280px 下 176px 下限会排到 6 列，每格实际约 195px；减去图标 34px + 间隙 + 右侧星标预留 36px，描述可用宽度只剩约 100px —— 中文 8 个字就到头。

方案

/* 放宽下限：宽屏 4 列而不是 6 列，描述能读到 16+ 字 */
.tile-grid { grid-template-columns: repeat(auto-fill, minmax(248px, 1fr)); }

/* 描述允许两行，超过才省略（比单行截断更诚实） */
.tile-desc {
  white-space: normal;
  display: -webkit-box; -webkit-line-clamp: 2; -webkit-box-orient: vertical;
  overflow: hidden;
}
.tile { align-items: flex-start; }  /* 两行时图标不再垂直居中 */

已验证的约束：data-tile-cols 的期望值写在 panel-shot.mjs 里（560px→3 / 400px→2 / 1280px→6），改下限必须同步更新那三处断言，否则套件会报红。

4P1 · 一致性与规范

单个都不致命，叠在一起就成了"这个产品没被一个人统一看过一眼"。

P1-1

同一个功能有三套名字，还有一处错字

现象

磁贴标签、卡片头标题、内容区居中标题 —— 三者各写各的：

磁贴卡片头标题内容区标题
PCD 过期获取 PCD 过期数据获取 PCD 过期数据
获取文件数据根据上传文件获取数据批量查询订单状态
SOQL 导出SOQL 数据导出SOQL 查询
批量导入批量数据导入Data Import
T-4 OutstandingOutstanding T-4 connectivity获取 T-4 报表数据
中午食乜中午吃乜今天中午吃什么？

Org 看板更是有四个叫法：首页面板「Org 状态」/ 磁贴「Org Limits 用量」/ 卡片头「Org Dashboard」/ 内容标题「Org Limits 用量」。

根因

三套文案的物理来源本身就是三处：src/rules/ui_layout.json（+ ui_layout_default.js 副本）的 label、index.html 的 .ant-card-head-title、index.html 的 .section-title。

方案

定一条规则并写进 check:ui.mjs：

/* 三处的措辞约束 */
磁贴 label  = 名词/短语，2–6 字，可截断（「PCD 过期」）
卡片头 title = 与磁贴完全同字（一键跳转 → 落到哪张卡，看头就知道）
内容标题     = 动词短语，可含完整口径（「获取 PCD 过期数据」）

/* 例外：宽屏下内容标题已在 P0-3 改为与图标同行的小标题，
   若采纳「取消内容区重复标题」则只需维护两处 */

先做纯文本修正（含「食/吃」）：中午食乜 统一为 中午吃乜（界面其余中文均为通用语，混合粤语会让搜索与记忆都变差）。

P1-2

主按钮圆角 2px，与全站 6–12px 硬冲突

现象

连接设置页的三个全宽按钮、午餐页的按钮是近乎直角；而卡片是 12px、输入框是 6px、徽标是 999px。同一屏里出现"直角按钮 + 圆角输入框"。

根因

main.css:745

.ant-btn-lg { height: 40px; padding: 6.4px 15px;
  font-size: var(--fs-lg); border-radius: 2px; }  ← 从 antd 3.x 抄来的死值

全站只有 4 处用到（index.html:152 / 176 / 227 / 1253）＋ popup 1 处，所以影响面小但很显眼。

方案

.ant-btn-lg { border-radius: var(--radius-md); }  /* 6px，与输入框一致 */

顺带把 .fetch-btn（主 CTA，48px 高）的圆角也显式写 var(--radius-md)，别依赖 antd 默认值 —— 现在它靠"没被 ant-btn-lg 覆盖"侥幸正确。

P1-3

同一组 Org Limits 数据，首页与详情页是两种卡片

现象

首页仪表盘卡：整块底色变黄/变红（--warning-bg / --error-bg）。详情页汇总卡：白底 + 顶部 3px 色条。同一份数据、同一个语义，换页就换了表达语言。

证据

对比下方 rev-home-panel-400（黄/粉整块底）与 rev-limits-tab-1280（白底 + 顶条）。

根因

main.css:3140（.org-dash-gauge.is-warn/.is-danger）vs 2770（.org-limit-card 的 border-top: 3px）

两处是不同时期写的，各自选了"最醒目"的做法。

方案

推荐统一为「白底 + 顶部 3px 色条」：理由是一行四张卡里出现两块彩色底，会让人误以为那两张"选中了"或"坏了"，而顶条能在保持卡面同质的前提下传达状态。

.org-dash-gauge {
  background: var(--bg-primary);
  border-top: 3px solid var(--success-color);
}
.org-dash-gauge.is-warn   { border-top-color: var(--warning-color); /* 去掉整块底色 */ }
.org-dash-gauge.is-danger { border-top-color: var(--error-color); }
.org-dash-gauge.is-over   { border-top-color: var(--error-strong); }

状态仍由三处冗余表达：顶条颜色 + 数值颜色 + 「超额」标记 —— 不会丢信息。

P1-4

详情页双标题：卡片头一遍，内容区又一遍

现象

「Org Dashboard」在卡片头，「Org Limits 用量」在下方居中的大标题；「获取报表数据」和「获取报表统计数据」同理。用户在 200px 的垂直距离内读到两个"这是标题"的元素。

根因

src/index.html:1877（.ant-card-head-title）+ 1888（.section-title）—— 每个 section 都这样

方案

把 .section-header 降级为「卡片头下方的说明条」：小图标 + 说明文字，去掉重复的大标题。若担心 SEO/可访问性，标题元素保留但 visually-hidden。

<div class="section-header">
  <div class="section-icon u-bg-theme"><i class="fas fa-chart-bar u-text-brand"></i></div>
  <div class="section-info">
    <!-- 标题移入 .section-info，与卡片头同字，视觉上从属于它 -->
    <ul class="section-desc">…</ul>
  </div>
</div>

注意 src/index.html 里已有 .section-info 的使用先例（下方模板），复用它即可。

P1-5

状态徽标三种形态，语义靠颜色猜

现象

「插件偏好」页里：v68.0 是淡紫底胶囊、右侧 是无底蓝字（像链接）、已关闭 是灰底胶囊。三者同为"当前值"，却长得像三种控件。

根因

main.css:2112 .pref-group-value 的 [data-side=unknown] / [data-state=on|off] 分支各自定义，没有共同骨架

方案

.pref-group-value { /* 统一骨架：胶囊 + 等宽 + 一致 padding */
  padding: 2px 10px; border-radius: 999px;
  font-family: var(--font-mono); font-size: var(--fs-sm);
}
/* 只用「底/字色」表达状态，不再切换是否有底 */
.pref-group-value[data-state="on"]  { background: var(--success-bg); color: var(--success-color); }
.pref-group-value[data-state="off"] { background: var(--bg-secondary); color: var(--text-secondary); }
P1-6

时间格式三套并存，其中一套是英文 AM/PM

现象

Org Limits 页脚「上次刷新：10/13/2026, 11:51:35 AM」—— 全中文界面里唯一的英文时间。同一项目里另有两处不同写法。

根因

位置写法结果
biz/org_limits.js:412new Date(x).toLocaleString()跟随浏览器语言 → 英文 AM/PM
biz/session_info.js:130dayjs().format("YYYY-MM-DD HH:mm:ss")正确
biz/ui.js:2140toLocaleString('zh-CN', {…})可用但第三套

方案

// 项目已有 dayjs（index.html 同步引入），统一走它
const timeText = lastFetchedAt
  ? `上次刷新：${dayjs(lastFetchedAt).format("YYYY-MM-DD HH:mm:ss")}`
  : "尚未刷新";

顺手把三处收敛成一个 common/utils.js 的 formatDateTime()，并加进 check:ui 禁止 toLocaleString() 无参调用。

5P2 · 打磨项

P2-1

仪表盘没有刻度，60% / 85% 这条最重要的信息看不见

现象

指针旁没有任何数字，axisLabel: { show: false }、detail: { show: false }，splitLine 只有 4px 的短刻线。用户无法判断"指针指到 75% 到底离危险区多远"。

方案

// ① 分区带的语义要能读出来：在 60/85/100 三个阈值位置加标签
axisLabel: {
  show: true, distance: 14,
  fontSize: 10, color: "#8c8c8c",
  formatter: (v) => [60, 85, 100].includes(Math.round(v)) ? v + "%" : ""
}
// splitNumber 需同步调整，让 60/85 落在刻度点上（0/5/10…100 步长 5）

诚实标注：ECharts gauge 的 axisLabel 只作用于均分刻度，阈值不一定正好落在刻度点上；落地前必须实测（?sf=mock 可复现仪表盘）。若实测不可行，退路是在卡片数值下方补一行 10px 的「警告 60% · 危险 85%」说明。

P2-2

窄栏顶栏 5 个元素挤一行

现象

400px 下顶栏要放：logo + 「已连接」绿 tag + 「Production」红 tag + 设置按钮 + 宿主切换按钮 + 头像。红 tag 尤其占宽（"Production" 9 字符），而它的信息在头像菜单里也有一份。

方案

@media (max-width: 560px) {
  /* 环境徽标只在宽屏显示；侧边栏下靠「连接状态」tag 的底色区分 */
  .env-indicator { display: none !important; }
}
/* 若必须保留：只留一个字母 P / S，并加 title 属性 */

注意现有 768px 那条 .env-indicator { display: none } 被内联样式压着从未生效（main.css:3529 已有注释说明），所以必须带 !important。

P2-3

4 个分组各自只有 1 项，各占一整行卡片

现象

数据分析 / OTT / CVP7 / 杂项 各 1 项。首页因此有 4 张只有一格的卡片，右侧大片空白，竖向节奏被切得很碎。

方案

两种走法，选一种：① 合并 —— 把 1 项分组并入「其他工具」；② 组内一行多列 —— 保持分组语义，但让 auto-fill 在内容少时不要撑满（把网格改成 repeat(auto-fill, 248px) 而非 1fr，磁贴就不会被拉宽）。② 更保守，不动 ui_layout.json 的分组结构，也不影响 check:ui 的磁贴↔section 对齐断言。

P2-4

星标键盘不可达；窄屏常显后语义反转

现象

「加入常用」星标是 <span data-action="toggle-fav">：只有 title，没有 tabindex、没有 role、没有 aria-pressed —— 键盘用户完全够不到。窄屏下它被强制 opacity: 1 常显，未收藏的灰色 ☆ 看起来像"已收藏但禁用"。

方案

<!-- 改成真正的按钮 -->
<button type="button" class="tile-fav-btn"
        data-action="toggle-fav" data-tile-id="…"
        aria-pressed="false" aria-label="加入常用功能">☆</button>

/* 常显时用「描边空心 vs 实心金」拉开差距，别只靠明度 */
.tile-fav-btn { color: var(--border-color); }          /* 未收藏：极淡 */
.tile-fav-btn.is-on { color: var(--warning-color); }     /* 已收藏：金色 */
.tile-fav-btn:focus-visible { opacity: 1; outline: 2px solid var(--primary-color); }
P2-5 / P2-6

两处小尺寸问题

设置页

宽屏箭头漂移：.settings-row 是全宽，1280px 下右箭头离文字约 900px。建议 .settings-list { max-width: 720px }，或在 ≥1024px 时改为两列。

窄栏 gauge

表盘过小：400px 两列时容器约 170×104，radius: "100%" 取 min 边 → 表盘直径仅 104px，指针长 60px，splitLine 4px 的分度线在这个尺寸下几乎不可见。建议窄栏把两列改为一列（@media (max-width: 480px) { .org-dash-grid { grid-template-columns: 1fr } }），并让 .org-gauge-chart 高度随宽度用 aspect-ratio 而非固定 104px。

7目标态：详情页两种版式
