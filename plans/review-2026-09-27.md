## 1. P0：仓库与凭据（最高优先，建议今天处理）

### 1.1 公开仓库里有两个 Microsoft Graph 访问令牌

- `src/common/graph_token.js` 里硬编码了一个 JWT 访问令牌，`src/common/graph_token`（无扩展名）里是**另一个**不同的令牌。
- 两者都被 git 跟踪，且**都存在于公开远端** `https://github.com/iamnicwu/nForce-tools`（`private: false`，`pushed_at 2026-09-25`）。
- JWT payload 明文包含：真实姓名（`Wu, Nick YF`）、`oid`、租户 ID、内网/出口 IP（`42.200.58.237`）、客户端应用（Graph Explorer）。
- 授权范围（`scp`）很宽：`Mail.ReadWrite`、`Files.ReadWrite.All`、`Directory.Read.All`、`Chat.ReadWrite`、`Sites.ReadWrite.All`、`TeamsActivity.Read` 等。

**缓解因素**：两个令牌的 `exp` 均为 2026-07-10，已过期约 2.5 个月，所以当前不存在"立即可被滥用"的窗口。

**真正的风险在于模式**：这个文件按注释设计就是"把新 token 替换进去"，**下一次刷新 token 就等于把一个可用的 Graph 凭据提交到公开仓库**；而 `git` 历史会永久保留已泄露的两份。

**建议动作（按顺序）**：

1. 立刻到 Microsoft Entra / Graph Explorer 侧确认该会话已失效；如仍能刷新，先撤销授权（`Revoke sessions`）。
2. `graph_token.js` 增加进 `.gitignore`，并从工作区删除；令牌改从 `chrome.storage.local` 读取（`background.js` 已经在做 OneDrive 代理，读取入口是现成的）。
3. 清理历史（`git filter-repo --path src/common/graph_token.js --path src/common/graph_token --invert-paths` 或 BFG），然后 `git push --force-with-lease`；**注意 fork/clone 缓存仍可能留副本，所以"撤令牌"永远优先于"清历史"**。
4. `src/common/graph_token`（无扩展名，3.3KB，疑似历史残留/备份）直接删除。

## 3. P1：性能

### 3.1 启动 / 加载（杠杆最大）

`src/index.html` 的 `<head>` 里是 5 个 **同步阻塞** 脚本，全部没有 `defer`/`async`：

| 文件 | 体积 | 是否首屏必需 |
|---|---|---|
| `lib/js/jsforce.min.js` | 1.37 MB | 连接后才用 |
| `lib/js/echarts.min.js` | 1.00 MB | 仅 3 个图表页 + Org 面板 |
| `lib/js/xlsx.full.min.js` | 0.85 MB | 仅上传/导出时 |
| `lib/js/jszip.min.js` | 95 KB | 仅 Bulk ZIP / Metadata 合并 |
| `lib/js/dayjs.min.js` | 7 KB | 是 |
| **合计** | **≈3.32 MB** | |

排版上还要加上：

- `antd.min.css` **545 KB / 5,522 条规则**，而全项目（JS+HTML）实际只用到 **43 个 `ant-*` 类名** → 按类名收敛可裁掉 **91.7%（≈456/5522 条规则，545KB → ≈45KB）**。
- `lib/js/papaparse.min.js`（19 KB）**全项目零引用**，但仍被 CopyPlugin 复制进 dist。
- `dist/lib/js/.DS_Store` 被复制进扩展包（`src/lib/js/.DS_Store` 存在，CopyPlugin 的 `from: 'src/lib/js'` 会连它一起拷）。

**为什么这条尤其重要**：侧边栏是主入口（`side_panel.default_path = index.html`），**每点一次工具栏图标就重新加载并解析一次 index.html**。3.3MB 阻塞 JS 是每次打开面板的固定成本，跟用户实际要做什么无关。

**建议**：

1. `echarts` / `xlsx` / `jszip` 改为**按需动态 `import()`**（echarts 在进入 section-10/13/27 或首页面板首次需要时加载；xlsx 在 `excel_utils` 首次调用时加载）。首屏只剩 `dayjs`（7KB）+ `jsforce`（连接页才需要，甚至可延后）。
2. 至少给保留的脚本加 `defer`（注意：`app.js` 是 `type="module"`，本身已是 defer 语义；但 `sf_service.js` 依赖全局 `jsforce`、`session_info.js` 依赖全局 `dayjs`，所以引入顺序仍需保证）。
3. antd 做**按类名 purge**（`purgecss` 或一次性离线裁剪），把 43 个类名作为 safelist 的白名单来源；注意 JS 里动态拼的类名（`ant-alert-${type}`、`ant-tag-${level}` 等）必须显式加进 safelist。
4. CopyPlugin 加 `globOptions: { ignore: ['**/.DS_Store'] }`，并删掉 `papaparse` 的复制。

### 3.2 运行时热点

**① Org Limits 搜索框：每次按键全量重建 + 重建 4 个 ECharts 实例**

```js
// src/biz/org_limits.js
414: filterInput.addEventListener("input", () => render());
// render() 内部：
397: disposeGaugeCharts(host);
398: host.innerHTML = `...`;     // 整个列表 + 汇总卡重建
418: initGaugeCharts(host);      // 重新 echarts.init 4 次
```

输入 "storage"（7 次击键）= 7 次全量 DOM 重建 + **28 次 `echarts.init`/`dispose` 配对**。ECharts 实例创建在 canvas 上是重操作，体感就是输入卡顿。

**建议**：`input` 事件加 150–250ms debounce；并且**过滤只重渲染列表区**（把汇总卡/仪表盘的 DOM 挪到独立宿主，`render()` 拆成 `renderSummary()` + `renderList()`），仪表盘只在数据变化时重建。

**② 首页面板同样被高频重建**

`ui_layout.js:442 refreshHomeDashboard()` 在 `renderLauncher()` 里，而 `renderLauncher()` 被 `onSessionRestored` / `watchSessionStorage` / `persistFavorites` / `applyLayoutFromPanel` 等**多处**调用。而 `renderHomePanel()` 每次都 `disposeGaugeCharts(host)` + 重建 + `initGaugeCharts(host)`。

后果：**在首页点一次 ☆ 加入常用功能，就会销毁并重建 4 个 ECharts 实例**（`persistFavorites` → `renderLauncher`）。点 8 次 = 32 个实例的创建/销毁。

**建议**：把"Org 面板"拆成独立渲染入口，磁贴/常用功能的重渲染不触发它；或在面板内部做脏检查（数据未变则只更新 class，不重建 DOM）。

**③ 表格渲染逐单元格操作**

```js
// src/common/table_utils.js:57-78
displayData.forEach((row, rowIndex) => {
  const tr = document.createElement("tr");
  ...
  columns.forEach(col => {
    const td = document.createElement("td");
    ...
    td.style.maxWidth = "300px"; td.style.overflow = "..."; // 每格 4 次样式写
    tr.appendChild(td);
  });
  tbody.appendChild(tr);
});
```

1000 行 × 13 列 ≈ **13,000 次 `createElement` + 13,000 次 `appendChild` + 52,000 次样式写**，且每次都触发布局计算。

**建议**：改用 `DocumentFragment`（或直接字符串拼 HTML 一次性赋值），把 4 条固定样式提到 CSS 类（如 `.ut-cell`）里，斑马纹也用 `:nth-child(odd)` 而不是逐行写内联 `background`。预期 3–10× 提升。

**④ t2rules 每行重复扫描 key 数组**

```js
// src/common/t2rules.js:124-148
function getValue(row, ...possibleNames) {
  const keys = Object.keys(row);   // 每次调用都新建一次键数组
  ...
}
function setValue(row, colName, value) {
  const keys = Object.keys(row);   // 同上
  ...
}
```

`extractContext()` 每行调用 `getValue` **11 次**，加上 `setValue` 2–3 次 → 每行约 14 次 `Object.keys()` 分配。5000 行数据 = 7 万次键数组分配 + 数十万次字符串比较。

**建议**：在 `applyT2Rules` 入口按首行建一次 `列名 → 实际 key` 的映射表（`Map`），后续按映射直取；`getValue` 保留作为兜底即可。

**⑤ `applyRules` 给既有行新增键**

```js
// src/common/excel_utils.js:772
row[targetKey] = action.value;
```

给已定型的对象新增属性会让 V8 的 hidden class 反复变形（deopt）。数据量大时（`IMPORT_MAX_BATCH`/`maxFetch` 都是万级）会明显变慢。

**建议**：分析前先算好目标列全集，一次性用对象字面量构造新行（或在 `sheet_to_json` 后统一 `defval` 补齐列）。

**⑥ 事件监听日志全量重渲染 + 每次全量 stringify**

```js
// src/biz/inspector_tools.js:686-705
host.innerHTML = eventLog.map((ev, idx) => `...${escapeHtml(JSON.stringify(ev._data, null, 2))}...`).join("");
```

每来一个事件，都会把**最多 200 条**的事件全部序列化并重建 DOM → 单事件 O(N)，高频事件流下退化为 O(N²)。

**建议**：改为增量插入（`unshift` 单个节点 + 超过 200 时删尾），并且对 `_data` 做**懒序列化**（展开时才 stringify）。

**⑦ Metadata 合并时的 base64 解码方式**

```js
// src/biz/inspector_tools.js:574
const files = blobs.map(b => new Uint8Array(atob(b).split("").map(c => c.charCodeAt(0))));
```

`atob(b).split("")` 会构造一个与 base64 字符串**等长**的中间字符数组。一个 30MB 的 metadata zip，base64 是 ~40MB 字符串 → 中间数组 4000 万个元素，极易卡死/爆内存。

**建议**：`fetch("data:application/zip;base64," + b).then(r => r.arrayBuffer())`，或手写分块 `Uint8Array` 解码。

**⑧ `escapeHtml` 每次都 `createElement('div')`**

```js
// src/common/utils.js:201-207
const div = document.createElement('div'); div.textContent = str; return div.innerHTML;
```

`renderSoqlResults` 里**每个单元格调用 2 次**（`title` 属性 + 文本），500 行 × 10 列 = 10,000 次 DOM 元素创建。

**建议**：改成纯字符串替换（`& < > " '` 五个），或复用一个常驻 div。

**⑨ 登录页串行网络 + 去重被注释掉**

```js
// src/login_app.js:121
// const processedDomains = new Set();     ← 被注释
...  for (const tab of tabs) { await testConnectionWithUserInfo(sid, instanceUrl); }
```

- 去重逻辑被注释掉了：同一个 org 开 5 个 Salesforce 标签页，就发 5 次 `conn.identity()`。
- 全部串行 `await`，每个 tab 至少一次网络往返，标签页多时登录页要等很久。

`src/biz/logic.js:51 autoDetectSession()` 里保留了 `processedDomains` 去重，但那个函数本身是死代码（§4）。**建议以 logic.js 那版为准修 login_app.js，并把 identity 探测改为 `Promise.all` 并发（加并发上限）。**

**⑩ 报表数据先写 OneDrive 再导出**

```js
// src/biz/logic.js:422（getReportData 内）
const writeResult = await writeReportDataToOneDrive(result.data);
...
exportReportData();
```

`writeReportDataToOneDrive` 默认 `batchSize: 200` / `batchDelay: 300ms`。5000 行 → 25 批 → **光固定延迟就 7.2 秒**，再加 25 次网络往返。这段时间用户既看不到文件下载，也不知道在等什么。

另外这属于**默认把完整报表数据外发到第三方存储（OneDrive）**，从数据治理角度应当是可选项而非默认行为。

**建议**：改成 fire-and-forget（不 `await`）或用 `showNotification` 单独汇报结果；导出不要被它阻塞；把 OneDrive 写入改成显式开关。

**⑪ 其余小项**

- `main.css` 有 **15+ 处 `transition: all`**（`:240/:298/:503/:825/:1134/:1976/:2129/:2214/:2345/:2479/:2893/:3035` 等），建议改为具体属性（`background-color, color, transform`），避免不必要的布局属性过渡。
- `index.html` 有 **200+ 处内联 `style="..."`**，1716 行 HTML 中混了大量样式，应下沉到 `main.css`（也便于主题化）。

## 5. P2：逻辑缺陷（非性能）

1. **手动登录丢 `instanceUrl`**（`src/login_app.js:447`）
   ```js
   const result = await testConnectionWithUserInfo(sessionId);   // 只传了 1 个参数
   ```
   `instanceUrl` 为 `undefined` → jsforce 回退到默认 `login.salesforce.com`；随后 `:455` 读 `result.userInfo.instanceUrl`（该字段不存在）→ 会把 `sf_instance_url` 写成 `null`。
   **修**：`testConnectionWithUserInfo(sessionId, <用户填的或推断出的 instanceUrl>)`，并在 `result` 里显式返回 `instanceUrl`。

2. **全局错误处理器自身可能二次抛错**（`src/app.js:1567-1576`）
   ```js
   showNotification(`发生未处理的错误：${event.reason.message || event.reason}`, 'error');
   ```
   `event.reason` 为 `undefined`（`Promise.reject()` 无理由时）→ 读 `.message` 抛 TypeError。同一问题在 `:1579-1588` 的 `event.error.message`。
   **修**：`event?.reason?.message ?? String(event?.reason ?? '未知')`。

3. **未连接白名单不一致**（`check:ui` D 组 WARN）
   磁贴「中午食乜」(step 14) 声明 `requiresConnection: true`，但 `step 14` 不在 `CONNECTION_REQUIRED_STEPS`、section 也没有 `needs-connection` → 未连接时磁贴**看着可点**，点进去却被 `showSection` 弹回连接页。纯本地功能，应把 `requiresConnection` 改成 `false`。

4. **`Bulk Job` 结果 CSV 拼接**：`getBulkJobResults` 用 `allCsvData += csvText`（`sf_service.js:981`）逐页累加，几十 MB CSV 会有多次大字符串拷贝；建议用数组 `push` + 末尾 `join`。

## 6. P3：工程化护栏与测试

`npm run check:ui`（`tools/check-ui.mjs`，957 行，A~K 共 11 组守卫）质量已经相当高，当前 `ERROR 0 / WARN 2`。可以在此基础上补两组**最容易踩的坑**：

## 7. 做得好的地方（保持）

- **日志体系**：`common/logger.js` 统一四级 + TAG 前缀 + `maskSecret()`，并用 check-ui 的 K 组**禁止裸 `console.*`**，这条自律在同类项目里很少见；`background.js` 作为 ESM service worker 复用同一模块也很干净。
- **DOM 访问收敛**：`common/dom.js` 的 `$` / `on` / `onAll` 在元素缺失时只 warn 不抛，配合 `bindEvents()` 外层 try/catch，消灭了"页面正常但按钮点不动"这类难查故障。第一方代码里已无裸的 `getElementById(...).addEventListener`（实测 0 处）。
- **设计令牌化**：`main.css` 的 `:root` 是字号/颜色/图标尺寸的单一来源，并有 check-ui 的 I 组守卫（字号越界 0 处、硬编码色 0 处）。
- **启动顺序设计**：先渲染界面、再"尽力而为"恢复会话，且区分"服务端判定失效（401 / INVALID_SESSION_ID）"与"请求被 CSP/网络拦截"，避免误降级为未连接——这是很成熟的取舍。
- **`sessionReady` 时序门闩**（`org_limits.js`）：session 确认可用前绝不发 limits 请求，避免了拿过期 session 打接口。
- **CSP 与 host_permissions 对齐**：实测 `host_permissions` 的 15 个域名全部出现在 `connect-src` 里，无遗漏。
- **侧边栏/标签页双宿主同步**：`watchSessionStorage()` 只读不回写，天然避免循环触发。
